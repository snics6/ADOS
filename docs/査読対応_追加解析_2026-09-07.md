## 依頼1：活動長を統制した偏相関（85件すべて）

### 手続き（既存16関連と同一であることを検証済み）

現行の実装は **Spearman 偏相関の公式**（順位に直してから Pearson の偏相関公式）である：
`src/ados_ffm/exp3_findings.py` の `spearman_partial(x, y, z)`．

```python
rx, ry, rz = rankdata(x), rankdata(y), rankdata(z)   # 欠損を落とした後の完全ケースで順位付け
rho_p = (rxy - rxz * ryz) / sqrt((1 - rxz^2) * (1 - ryz^2))
```

依頼にあった「順位残差化か公式か」については，**両方を計算して差を確認した**：
順位残差化（`rz` に対する `rx`・`ry` の線形回帰残差どうしの相関）との差は
85件すべてで **最大 2.8e-16**，すなわち数値誤差の範囲で完全に一致する．
これは代数的にも当然で（Pearson の偏相関 = 残差相関），**どちらで書いても同じ値**である．
論文には「Spearman 偏相関（順位変換後の Pearson 偏相関）」と書けばよい．

**同一性の検証**：既存の `outputs/hetero/duration_partial.csv`（反転8対の16関連）と，
新スクリプトが同じ16行に対して出す値を突き合わせた．
`rho` / `rho_partial` / `rho_x_duration` / `rho_y_duration` / `n` の
**最大差はすべて 0.000e+00**（完全一致）である．

## 依頼3：情報源プロファイルの半分割再現（旧 0-b）

### 結論：**現行の枠組みでは追試できない．**「できなかった」で確定してよい．

旧 0-b の定義（`docs/old/議論まとめ_実験手順書.md` §0-b，`docs/old/検証ログ.md` Phase 3）：

- 単位 = **(ADOS項目 × 課題)**．各単位で child / examiner / dyad の LOPO 性能を出し，
  3次元ベクトルを作る
- 標本を2分割し，各半分で **LOPO を再計算**，両半分の3次元ベクトルの Spearman 順位相関を取る
- 3情報源すべて status=ok の単位のみ対象．ランダム分割100回．主指標＝セル平均の平均
- 旧結果：mean rank Spearman ≈ **−0.016**（n_ids=56，mean_n_cells≈72.5），合格基準 ≥0.50 に対して fail

現行の枠組みで足りないものを，種類別に挙げる．

#### (1) 単位が存在しない — 実装（データはある）

現行の目的変数は `ados_ffm.data.TARGETS` の **SA / RRB / CSS の3つだけ**である．
旧 0-b の単位である「ADOS項目」を目的変数にする経路が現行パイプラインに無い．

- 項目得点そのものは `data/ADOS2_result_2.xlsx` にある（29項目）ので**データは足りている**
- しかし Stage A・閾値・当たりセルはすべて3得点向けに作られており，項目別に回すには
  実験1・実験2を29目的変数で作り直すことになる．それは現行の枠組みでの追試ではなく，
  **第1世代の枠組みの再建**である
- 現行の単位に読み替えると (課題 × 得点) = 最大 **30**．旧 0-b の実効 **≈72.5** を下回る

#### (2) 3情報源がそろうセルが5つしかない — 実装

実験2は **Exp1 の FDR 当たりセルだけ**を走らせる（`outputs/exp2/run_meta.json`：
`"cells": "Exp1 FDR hit cells only"`）．その41セル・23の (課題, 得点) のうち，

| 情報源がそろう数 | (課題, 得点) の数 |
|---|---|
| 3（child・examiner・dyad） | **5** |
| 2 | 8 |
| 1 | 10 |

0-b の主指標は3要素ベクトルの順位相関なので，**使えるのは5単位**である．
3要素の Spearman は {−1, −0.5, +0.5, +1} の4値しか取らないため，5単位の平均は指標として成立しない．
30単位すべてを埋めるには実験2を全90セル（10課題 × 3得点 × 3情報源）で走らせる改修
（`ados_ffm.exp2.prepare_jobs`）が必要で，現行スクリプトには無い．

#### (3) 選択が全データで固定されている — 実装（二重使用）

Stage A の閾値 τ は `outputs/exp1/thresholds.json` に **59名全員で固定**されている．
半分割の中でこれを使えば漏れが入る．正しくやるなら半分ごとに τ を引き直す必要があり，

### 4-2. ジェスチャ・姿勢事象の検出規則

`ados_extract` 側は事象を**数えるだけ**である（`src/ados_extract/windows.py`）：

```python
EVENT_TYPES = ("pointing_candidate", "arm_extended", "fidgeting",
               "hand_near_face", "leaning_away")
```

`ges_{role}_{event}_per_min` は，課題区間に入る 0.25 秒フレームのうち，その役割の `pose.events` に
その型が現れたフレーム数を数え，**和集合の総時間（分）**で割った値である
（同一フレームに同じ型が複数あっても 1 と数える）．

**検出規則そのものは上流パイプライン（`multimodal_v3` / pose_v2 生成器）にあり，そのコードはこの
研究室PC上に存在しない．** 配布 JSON の事象は `{type, start, end, confidence}` だけを持ち，
しきい値は記録されていない．

そこで，**配布データから規則を逆算した**．pose_v2 の各フレームは `features`
（`joint_jitter`, `hand_to_face_dist`, `left/right_elbow_angle_deg`, `left/right_wrist_speed`,
`torso_lean_deg`, `head_drop`, `facing_angle_diff_deg`, `inter_person_distance`）を持つので，
事象の有無と突き合わせられる．**3名（020401 / d1_503 / g1_444）の全 53,775 フレーム**で検証した結果：

| 事象 | 逆算した規則 | 一致 |
|---|---|---|
| `fidgeting` | `joint_jitter > 0.08` | **完全一致**（TP 27,393・FP 0・FN 0） |
| `hand_near_face` | `hand_to_face_dist < 0.35` | **完全一致**（TP 269・FP 0・FN 0） |
| `arm_extended` | `max(left_elbow_angle_deg, right_elbow_angle_deg) > 155`（度） | **完全一致**（TP 13,580・FP 0・FN 0） |
| `pointing_candidate` | `arm_extended` かつ `max(left_wrist_speed, right_wrist_speed) < 0.08` | 再現率100%（FN 0）だが FP 478（一致率 99.1%）．**追加条件があるが，保存されている特徴では特定できない** |

- `pointing_candidate` の残差は `pose_quality` / `visible_joint_ratio` では説明できなかった
  （TP の最小値以上に FP が100%入る）．時間方向の条件か，`features` に保存されていない

- `leaning_away` も同様で，個人ごとの中央値中心化でも改善しなかった．

**まとめ方の提案**：`fidgeting` / `hand_near_face` / `arm_extended` の3つは規則を断定してよい．
`pointing_candidate` / `leaning_away` は「必要条件は特定したが，十分条件は配布データから復元できない」
と書く．事象名だけの列挙より強く書けるが，全部を断定はできない．
