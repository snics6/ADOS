# 課題区間の併合規則の修正（2026-09-07）

同一 `task_id` が複数回注釈されている場合の扱いを，**凸包（最小 t0 〜 最大 t1 の1区間）から
和集合（互いに素な区間の集合）へ**変更した．その結果として課題区間は「1つの連続区間」ではなく
「区間の集合」になるため，時間の連続性を仮定していた特徴の定義も決め直した．本ファイルはその記録である．

## 1. 何が誤っていたか

課題は中断・再開されることがあり（自由遊び → 別課題 → 自由遊び など），注釈は各ストレッチを
別行として記録している．旧実装（`src/ados_extract/task_segments.py` の `segments_for_participant`）は
これを `min(t0)`〜`max(t1)` の1区間に潰していた．あいだに挟まった別課題の時間まで飲み込むため，
その課題の「区間内の行動」から計算した特徴量が別課題の行動を含んでいた．

コホート59名での実測（`data/task_segments.json`，2026-09-07 時点）：

- 多ストレッチのセルは **11名・12セル**（うち1件は3ストレッチ）
- 凸包にすると **12名・27対**の課題区間が時間的に重なる
- 最悪の2例
  - `d1_503` ルーティン：2ストレッチ → 凸包 0:50–54:00（53分）．他7課題の全体を内包
  - `020471` ルーティン：2ストレッチ → 凸包 24:50–52:20（27分）．他6課題の全体を内包
- 和集合にすると重なりは **4名・4対**（25秒・20秒・6秒・5秒）だけになる．これは注釈上の
  境界の揺れであり，修正対象ではない

## 2. 新しい規則

注釈された各ストレッチの**和集合**をその課題の区間とする．ストレッチ間の空白は含めない．
重なる／接するストレッチどうしは結合するが，本当の空白は空白のまま残す
（`ados_extract.task_segments.merge_spans`）．

`segments_for_participant` は課題ごとに1エントリではなく**ストレッチごとに1エントリ**を返し，
各エントリは `stretch_index` / `n_stretches` を持つ．消費側は課題区間を
「互いに素な区間の集合」として扱わなければならない．

## 3. 決めた設計判断

区間が不連続になるため，次の3点を決めた．いずれも「空白時間は課題の外なので，そこをまたぐ事象を
課題内の事象として数える根拠がない」という理由による．

### (1) 境界をまたぐ事象 → **境界で必ず切る**

ターンはストレッチごとに構成し，連続ターン対（＝応答間隔・連鎖・FTO の材料）は
**同一ストレッチ内のペアのみ**とする．ストレッチをまたぐペアは捨てる．

実データの空白は最小20秒・最大1910秒であり，これを応答遅延として計上すると当該セルの
遅延指標が壊れる．なお連鎖（chain）は3秒閾値のため実データでは元々またいでいなかったが，
規則として明示した．

- `conversation.py`：`conversation_features` / `chain_initiator_features` / `_exchange_chains`
- `windows.py`：`extract_one` の応答構造ブロック（`rsp_*`）

### (2) 区間内変化（前半／後半） → **和集合の総時間の中点で分ける**

`_progress`（和集合の累積時間）の 0.5 を境に1回だけ分割する．分母は和集合の半分．
ストレッチごとに分けて平均する案は採らなかった：短いストレッチ（実演20秒など）で各半分が
10秒になり推定が不安定になること，ストレッチ数によって特徴の意味が変わり k=1 のセルと
比較できなくなることによる．

- `windows.py`：`_speech_window`（`win_*_delta` 6特徴）

### (3) レート系の分母 → **和集合の総時間**

`*_per_min` / `*_speech_frac` / `dyad_silence_frac` の分母は和集合の総時間とする．
旧実装では `conversation_features` だけが凸包長 `t1 - t0` を分母にしていた（これが今回の誤りの一部）．

## 4. コードのどこが何に依存していたか

### 凸包を作っていた箇所（1箇所）

- `src/ados_extract/task_segments.py` `segments_for_participant`

### 凸包に依存していた消費側

| 箇所 | 依存 | 対応 |
|---|---|---|
| `dynamics/extract.py` `t0=min(...), t1=max(...)` → `conversation_features(speech, t0, t1)` | 発話クリップ範囲・レート分母の両方が凸包 | `_task_spans()` で区間集合を作り，`conversation_features(speech, spans)` に変更 |
| `dynamics/conversation.py` `_clip(segs, t0, t1)` / `dur = t1 - t0` | 空白時間の発話（＝別課題の発話）を取り込む．分母が凸包長 | ストレッチごとにクリップ．`dur = span_total(spans)` |
| `dynamics/conversation.py` FTO・`initiate_frac`・chain | 連続ターン対が境界をまたぐ | 同一ストレッチ内のペアのみ (`pairs`) |
| `windows.py` `extract_one` 応答構造 | 同上（`rsp_after_exam_gap_*`, `rsp_long_silence_frac`, `rsp_child_reply_frac`, `rsp_n_exam_turns`） | `turn_groups` からストレッチ内ペアのみ |
| `exp3_findings.py` `extract_chain_initiators` | seg 1件ごとに1行を作る＝和集合化すると同一 (pid, task) が2行になり `set_index` が重複 | 課題ごとに区間集合へまとめて1行 |
| `exp3_findings.py` `ja_missingness` | `raw_rows[0]` の t0/t1 だけを表示 | 全ストレッチを併記 |

### もともと和集合で正しかった箇所（変更不要）

dynamics のマスク経由の特徴はすべて安全だった．理由は次のとおり．

- `extract.py` は同一 `task_id` の seg を OR してブールマスクにしていた
- `kinematics.py` / `crossmodal.py` の `adjacent_diff(a, isfinite(a))`：マスク外は NaN なので
  境界をまたぐ差分は NaN になる
- `kinematics.py` / `sync.py` の `contiguous_runs()`：窓・run・CRQA は連続 True の塊にしか張られない
- レート分母は `valid.sum() * GRID_SEC`（＝和集合），`_meta` の `duration_sec` も同じ
- `windows.py` の `dur` / `minutes` / `_progress` はすでに `_merge_intervals` の和集合基準
- `windows.py` の `_median_abs_angvel` は `0.1 <= dt <= 0.6` で境界跨ぎ差分を自動除外

### 67特徴のうち影響を受けるもの

| 区分 | 数 | 変化の理由 |
|---|---|---|
| `conversation_features` 由来 | 15 | 凸包の発話混入・凸包分母 |
| `rsp_*` | 5 | 境界跨ぎの間隔 |
| `win_*_delta` | 6 | 定義は据え置き（和集合中点）だが分母となる区間が変わる |
| 頭部・身体・sync・`ges_*`・`txt_*` | 41 | マスク経由．変化なし |

単一ストレッチのセルは値が完全に一致することを `020401`（全課題が単一）と `d1_503`（task 7, 10 が
多ストレッチ）で確認済み．変わったのは多ストレッチのセルだけである．
